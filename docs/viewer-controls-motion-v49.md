# 人工複眼VR v49｜AEGIS動作・操作UI・個眼選択の改修

## 1. AEGIS NAVY / SOLDIERの歩行と走行
v48ではX Botの歩行・走行の肩・腕関節クォータニオンをAEGISへ直接変換していたため、上半身が過度に左右へ広がり、肘が不自然に折れる動きが発生しました。

v49ではX Botの**周期と脚部の骨格運動**を維持し、AEGISの肩・肘・手首だけを、AEGIS自身の腕が自然に下がる基準姿勢へ戻して前後振りに限定しました。

- 肩の前後振り：歩行でおよそ±11度、走行でおよそ±16度
- 肘の屈曲：歩行約9度、走行約13度を基本とし、小さな周期補正を加える
- 手首：±1.8度程度の微小追従
- 足・骨盤・膝のX Botベースの動作対応は維持する

**制限：** AEGISにはX Botと同数の独立した関節はありません。32関節の動作をAEGISの13個の実スキニング関節へ対応させる方式は同じです。再リギングや接地IKを完了したわけではありません。人間の自然歩行を再現したと断定しません。

## 2. AEGIS全身連動パンチの拳の到達位置
パンチ動作の腰・胸・足の動きは維持し、右拳の到達点を右肩の外側固定位置ではなく、頭部と右肩の基準座標差から計算した**顔面中央の前方延長線**へ近づけています。

確認した代表ポーズでは頭部と拳のモデルX座標の差が約0.043モデル単位、Y座標差が約0.072モデル単位となりました。拳は顔の前方へ突き出していますが、頭部中心へ完全一致させる設定や対人の正しい標的判定ではありません。

## 3. 短い統一動作名
- X Bot：静止／構え／歩行A／歩行B／走行／パンチA／パンチB／パンチC／パンチD
- AEGIS NAVY・SOLDIER：静止・呼吸／構え／歩行／走行／パンチA／パンチB／踏み込み／腕上げ／腕伸ばし／肘曲げ

静止・構え、移動、パンチ、その他の順にカテゴリをまとめました。内部モーションIDは変更していないため、計測ログなどとの対応を維持しています。

## 4. 2～6眼の番号ラベルと個眼の単独表示
全個眼数で「1：左半身」「2：右半身」等の短い番号ラベルを表示できます。

- 右上の**番号ON/OFF**で表示・非表示
- 番号をクリックするとその個眼だけの映像を表示し、再クリックか「全表示」で戻す
- 単独表示中は他の個眼と中央全身の描画を無効にする（背景床グリッドは維持）
- **マーカーON/OFF**を独立させ、選択した個眼の対応関節に赤いマーカーを表示
- 双眼VRでは左右両眼に同じ番号ラベルを表示。GameSirのLBメニューから番号表示・マーカー表示・単独個眼を切替可能

注意：本表示は映像合成レイヤーの選択です。3Dモーションの元データ自体は変更しません。

## 5. 6眼の首・腰の位置
6眼の「1：首胸」は左右上肢の肩基準の高さへ、「6：腰」は左右脚の股関節基準の高さへ合わせています。腕や脚の動作に追従する従来の骨格座標を参照し、出力先の高さだけを調整しています。通常・双眼共通の描画計算値として適用します。

## 6. 通常ビューアのUI
不要な「2個眼 · 通常立体視 · 角度一致」等の大きいモードラベル、メッシュ数・v11説明、FPSの右下表示を非表示にしました。内部FPS計算やステータスは維持します。

- 左下：白字の短いモデル名（例：モデル：AEGIS NAVY）
- 右上：番号ON/OFF、マーカーON/OFF、双眼表示
- 個眼を単独選択中のみ「全表示」を追加
- 右下：**ズーム0.75×／1.00×／1.25×／1.50×／2.00×** の選択
- ズームはカメラ距離を共通の `state.zoom` で変更。通常ビューで設定した値を双眼VR・VRゲームへ持ち越す。モデル変更でもユーザー指定値を維持する

## 7. 検証と制限
Windows Edge WebGL2環境で、2眼ラベル、単独個眼、マーカーのON/OFF、双眼で左右2組のラベル、同じズーム値の維持、X Bot・AEGISの動作モーション、6眼の首・腰位置を確認しました。

従来のGameSirのVRメニューと移動、15通りの配置保存、実験A/B、モーション比較、CSV/JSON記録も回帰テストを通過しています。

iPhone Safari・GameSir実機・HMD装着時の最終視認性は未検証です。AEGIS歩行・パンチの「自然さ」は主観評価を含むため、今回の数値・描画チェックだけで完成を保証しません。
