# 人工複眼VR v50｜眼数別の公開配置・選択個眼の運動マーカー・Safari向け描画統一

## 1. 公開配置のデフォルト

ユーザー提供の2～6眼スクリーンショットに記載された値を**共通の公開初期設定**として採用した。3～6眼に限らず、2眼も対象。全パーツ共通倍率はすべて1.00倍。

| 個眼数 | 初期の広がり距離／水平間隔 | 全パーツ共通倍率 | 配置の考え方 |
|---|---:|---:|---|
| 2眼 | 0.080 | 1.00× | 左右半身を放射配置 |
| 3眼 | 0.105 | 1.00× | 左右上半身のみ広げる。両脚は中央全身と同じ投影位置に固定 |
| 4眼 | 0.100 | 1.00× | 2段×左右2列、水平間隔 |
| 5眼 | 0.105 | 1.00× | 放射配置 |
| 6眼 | 0.080 | 1.00× | 放射配置 |

デフォルトは `public-lens-defaults.json` の `eyeCountLayoutDefaults` に記載し、アプリで読み込む。個眼数ごとの変更値は `compoundeye.v50.eyeCountLayout` に独立して保存し、眼数切替や再読み込み時に復元する。旧 `compoundeye.v44.radialSettings` などの設定は削除せず、後方互換用に残す。

以前のSafari・Edgeローカル設定が新しい表示に影響しないよう、v50初回起動では旧「放射配置OFF」を移行し、v50の保存領域 `compoundeye.v50.radialMode` を使用する。再読み込み後も旧設定が復活しない。手動のモード切替はv50で永続化される。

### 3眼の両脚の位置

3眼の3番「両脚」は**元の中央全身の骨格アンカー投影座標（sourceUV）をそのまま表示位置（centerUV）に使用**する。距離を変えても座標上の追加移動を行わず、左右上半身1・2だけを放射移動する。脚部を表示する楕円の大きさと倍率は共通設定に従い、つま先表示を確保する。

## 2. 関節運動量の表示閾値（0～100）

サイドパネルに「関節マーカー表示閾値」のスライダーと数値表示を追加。初期値は **7/100**。右上のマーカーボタンには閾値をツールチップとして付ける。GameSirのLBメニューからも閾値プリセットを変更可能。

スコアは人体技能の良し悪しではなく、**3Dアニメーションの関節移動速度・角速度から計算した表示制御用の運動量**。概略は、モデル単位/秒の移動速度とrad/秒の角速度を重み付きで合成し、0～100にクリップ、前サンプルと平滑化した値。指先等は調整係数が適用される。

表示条件 `score >= threshold` の関節だけをマーカーとして描画する。閾値と個眼別ON/OFFは `compoundeye.v50.motionMarkerSettings` に保存。実験計測のJSONにも閾値・選択個眼・個眼ごとのマーカー表示設定を付加する。

## 3. 個眼選択時は、その部位の範囲内だけにマーカーを表示

- 個眼番号を選択して単独表示したとき、**関節の部位分類と、実際の楕円合成範囲の両方**を満たすものだけマーカー表示。
- 例：4眼の2番「右上半身」では、右肩・右上腕・右前腕・右手等が対象。左上半身や脚の関節は対象外。
- 表示座標は、元の3D骨格を局所映像へサンプリングする際の変換を逆にたどり、楕円境界から約10％内側までを許容範囲とする。
- 単眼・双眼の両方で、各眼の独立投影結果を使って範囲判定する。
- 選択中は右上の「マーカーON/OFF」が**その個眼の表示のみ**を変更。全表示時は従来どおり全体ON/OFF。個眼ごとの状態は端末へ保存。
- 比較用の差異リング・個眼ハイライトも、個眼単独表示中は同じ領域内に制限する。

## 4. Edgeの描画を基準としたSafari互換処理

v49までの描画用テクスチャは幅・高さを別々に上限値へ切り詰めていた。そのため、iPhoneなどの高DPR・縦長画面では**元カメラの縦横比と描画先テクスチャの縦横比が一致しない**場合があった。

v50では描画用テクスチャの幅・高さを**同じ縮小係数**で上限制御し、各眼の描画領域とオフスクリーン映像の縦横比を合わせた。さらにWebGL2のアンパック時のアルファ乗算・上下反転を明示的に無効化し、利用可能なブラウザでは描画色空間をsRGBへ指定した。これまでの床・中央全身の独立FBO合成は維持する。

Safari側に残った旧設定を基準へ戻すため、「**Edge基準の公開配置に戻す**」ボタンを追加。この操作は眼数別の値、表示方式、カメラ倍率を公開値に戻す。旧保存データはそのまま保管される。

**重要な留保**：同じ設定でも、PCの横長ディスプレイとスマートフォンの縦長画面では、視野の縦横比、実画面の大きさ、HMDのレンズ光学特性が異なる。全画面ピクセルの完全一致を意味しない。v50の目標は、同一の正規化配置、設定値、WebGL合成規則・縦横比が用いられることである。Windows Edgeでの検証は実施したが、iPhone Safari実機での再検証は未実施。

## 5. 検証

- Windows Edgeで2～6眼の初期値（0.080／0.105／0.100／0.105／0.080、倍率1.00）と眼数切替を確認
- 3眼の両脚の `centerUV == sourceUV`、距離変更時に左右上半身のみ移動することを確認
- 4眼の右上半身を単独選択し、各マーカーがその個眼の楕円内にあり、担当外関節が表示されないことを検証
- 閾値0／100、選択個眼マーカーOFF／ON、双眼の両眼表示を確認
- v49の旧ローカル設定（放射配置OFF・拡大倍率）から移行後、再読み込みしてもv50基準が戻らないことを確認
- 高DPR相当のスマホ表示とデスクトップ表示で、元の描画とFBOの縦横比が一致することを確認
- 既存のVR／GameSir・時刻同期比較・CSV／JSON機能の回帰テストを実施

人の運動技能・優劣はこの閾値から判断できない。画面の視認性と研究上の知覚効果は別の評価実験が必要。
