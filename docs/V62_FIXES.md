# v62 — YBot・運動連鎖タイムライン・AEGISパンチBの修正

**基準版**：v61公開版 `0ed4518`。直前の公開設定 `public-appearance.json` は内容・revisionを変更せず保持する。バックアップタグは `backup-v61-before-v62-20261112`。

## 1. AEGIS NAVY / SOLDIER パンチB

X BotパンチCをAEGISの13関節へリターゲットする従来経路を保ちつつ、頭・骨盤・大腿・下腿の回転の過大な変形を抑制した。骨盤を安定化させても胸と上腕のワールド方向が変わらないよう胸の局所回転を補償。元の開いた手指をパンチBの描画時のみ隠し、左右の手首ボーンに付随する一体型の丸い握り拳・袖口を表示する。これにより見た目の手首の分離を低減する。独立した指ボーンを新設したわけではない。パンチA/C、他動作、骨格の関節数は変更しない。

X Botの上腕・前腕方向はソースから移し、骨長はAEGIS固有の長さを保持する。脚部には意図的な安定化を加えるため、異骨格間で脚軸の角度が厳密に一致するとは主張しない。外観の見た目の妥当性と、実際の人体運動の自然さ・衝突の正しさは別である。

## 2. YBotは同一骨格の比較刺激

`ybot`はX Botの32スキン関節、全ノードの関節ID・名前・階層・バインド姿勢・骨長・座標系・元頂点を保持する。ソースGLBと頂点バッファは共通。描画時の色だけを変え、身体寸法や関節数は増減させない。異なるのは指定した動作トラックのみ。初心者の動きとは定義せず、**変更量が既知の合成刺激**とする。

`ybot-modifications.json` はパンチA/B/C/D別の設定。`joint_id`, `modification_type`, `requested_change`, `start_time`, `end_time`, `axis` を指定する。対応する種類は `time_shift`, `onset_shift`, `speed_peak_shift`, `rotation_peak_shift`, `local_time_shift`, `rotation_delta_deg`, `speed_waveform_deg`。時間ワープは解析区間の外で0に戻る窓を使い、回転量と短い周期変化を局所的に与える。意味を厳密に担保できない種類については**指定値＝観測ピーク差とみなさず**、再計算した実測差を別に保存する。

現在の既定例はX BotパンチAの関節ID 7の回転ピークを0.04秒遅らせる指定。30Hz近傍で再計算した実ピーク差は約0.0333秒。`motion_revision_id`、ソース動作、変更部位、指定量、再計算値、単位、期間、素材ハッシュ、検査品質を保持する。実際の値は再計算操作後の結果を優先する。

## 3. 運動連鎖タイムライン

3D表示の**下のページフロー領域**に折りたたみ可能な `運動連鎖タイムライン` を追加。PCでは余白へ、スマートフォン相当の幅ではスクロールして閲覧する。3D描画面には重ねない。任意の関節を選択・削除でき、各関節で移動速度か角速度を選択する。初期候補は右脚、骨盤、体幹、肩、上腕、前腕、手など。

横軸は元アニメーション時刻、縦軸は関節。状態は緑＝増速、橙＝減速、黄＝局所速度ピーク、灰＝低活動、薄灰＝欠損。円径は**同一関節・同一指標の指定区間における|速度変化率|の最大値を基準とする相対値**で、別部位間の力や技能を意味しない。表示と3Dマーカーは共通の `Kinematics54.states` と `peakCandidates` を使用する。

各関節の代表局所ピークを時間順に番号付けし、次イベントまでの時間差ms、ピーク速度と単位、前後の状態を右側に表示。イベントを選択すると3Dの元時刻へ同期。X/Y比較は同じ関節を上下二行に並べ、X＝塗りつぶし円、Y＝輪郭円。状態の色は共通。元時刻／動作局面0–100%を切り替え、実線X／破線Yの波形と同一ピークを重ねる。

ピーク時刻差・開始候補時刻差・ピーク値差・時間正規化後の差を表示。異単位の移動速度／角速度の比率は算出しない。タイムラインCSV/JSONにはソースハッシュ、動作改訂、関節ID、イベント順序、増減、差分、設定、品質を出力。JSONにはYBotの指定量と実測差、解析条件を含める。

## 4. CSV互換性／安全境界

XBotとAEGISは32対13関節であり、無理に対応しない。XBot/YBotは同一骨格・関節ID・関節名・座標・単位を確認し、比較不能なら止める。今後の実人体CSV向けにX/Y別々の入力欄を設けた。CSV入力では `data_schema`, `skeleton_id`, `joint_id`, `joint_name_source`, `coordinate_system`, `time_axis`, `linear_speed_unit`, `angular_speed_unit`、各関節の単調時刻と同一サンプル時刻を検査する。未検証の骨格対応は「関節対応が検証されていないため比較不可」。名前が似ているだけの関節IDは補間・同一視しない。XBot/AEGISの対応表は今回は作成しない。

**常時表示する注意**：表示される順序・増速・減速・ピークは、位置・姿勢から計算した運動学的特徴です。力・関節トルク・エネルギー伝達・技能の優劣を示すものではありません。

## 5. 回帰・既存機能

従来の複眼1〜6、単眼・双眼、魚眼、3Dマーカー、実験計測、統合CSV86列、イベントJSON、X/Y差分、配色とバイザー、公開された外観JSON、パンチA/C、歩行・走行を維持。YBotの新動作のみ新しい数値を持つ。AEGISパンチBは今回の修正によって値が変わるため新しい動作版IDを設定し、旧Bと混同しない。

**検証**：単体48件成功（運動学・過去機能40＋YBot／タイムライン8）。ブラウザ回帰は既存14、UI8、配色14、バイザー13、既存パンチ14、新機能15の合計78項目。Edge WebGL2で実際にモデル表示、A/B CSV読み込み、同一時刻の3D/タイムライン状態、YBotの既知変更、XBot/AEGIS比較停止、ピーク差の既存比較との一致、部位追加、画面幅、スライダー、動作境界、全既存動作を試験。結果は `docs/evidence/v62/` の各 `*-regression.json` とPNG画像を参照。

**未検証**：実機iPhone/Safari、実機HMD、実機GameSir、物理衝突／足底接地、実測データの技能評価、動作の因果関係・力学的伝達。約30Hzはアニメーションの再標本化周期であり、生体計測周波数ではない。
