# 人工複眼VR v48｜最大5動作のグラフ比較・GameSirの移動方向・AEGIS歩行/走行

## 主要変更

### 1. 3動作以上の比較

「実験計測」→「時刻同期・動作比較」で、A（基準）・B（比較）に加え、ボタンから比較C・D・Eの3セットを追加できます。**最大5動作**を一度に比較します。

- 関節ごとの色は全動作で共通。例：右手は水色、右前腕は橙色、左前腕は紫色。
- モーションごとの線種を変えています：**A 実線 / B 破線 / C 点線 / D 一点鎖線 / E 長破線**。
- グラフの上に、各モーションのアバター・動作名・線種と、各関節の日本語名・色を常時表示します。
- 3動作以上を選んだ場合は視認性を優先し、初期表示を運動量の大きい1関節に絞ります。関節選択から上位3関節や特定関節にも切替可能です。
- 元時刻と局面正規化（0〜100％）を選択可能。運動開始時刻と最大速度時刻は別々に記録します。
- 3Dモデルの半透明重ね合わせ／身体上の比較リングは、ドロップダウンで**比較B～Eから1つ選択**できます。全5モデルを同時に描画するわけではありません。VRで過密にならないようにするためです。
- 各比較動作に対して関節名を対応付け、比較できる骨格数・対応方法・単位と品質上の注意を表示します。
- 元時系列CSV、導出特徴CSV、**A対B～Eの比較差分CSV（比較IDを追加）**、元時系列JSON、解析条件・比較結果JSONを出力。スキーマは `compound-eye-motion-comparison-v2`。

### 2. GameSirの移動方向

VRゲーム中、左スティックで走行、十字キーで歩行する操作は維持。入力された進行方向を、現在の視点に対する世界方向に変換し、**アバターの向き（Y軸回転）を同じ進行方向へ合わせます**。

- 上・右・下・左の8方向／斜め方向に対応。
- Rスティックで視点が回っていても、その視点に対する入力方向で進み、アバターもそちらを向く。
- 移動入力が0の間は静止・呼吸へ戻り、最後の向きを保持。
- RBによる背面向き操作中も、ワールド方向が反転してしまわないように補正。

### 3. AEGISの歩行・走行の近似度・滑らかさ

X Botの `Boxer_Walk` と `Boxer_Run` の関節回転キーフレームを、X Bot／AEGISの基準骨格姿勢差から相対回転へ変換し、AEGISの既存関節へ対応付けました。

- キーフレームの周期末尾8％を始点へ滑らかにつなぐ補間。
- 前後の近接サンプルによる小さな周期内平滑化。
- 足首・つま先のソース回転を、AEGISに存在する下腿ボーンへ限定的に合成（足の持ち上げと踏み込みを近似）。
- GameSirで歩行・走行・待機を切替える際、約190msの姿勢クロスフェードを適用。

**物理的なボーン数についての重要な留保：** X Botには32本のスキニング関節があり、AEGISのメッシュに実際にウェイトを持つ関節は13本です。32関節のX Botの動作をリターゲットすることはできますが、AEGISの実骨格を32関節に増やしたわけではありません。実際に指・足首・つま先・細かい体幹まで独立変形させるには、AEGISメッシュの再リギング（ボーン構造・ウェイト・逆バインド行列）と足の接地IKが必要です。

## 検証

- Edgeで5動作・3関節を選ぶと、最大15本の曲線が関節別同色・動作別線種で描画されることを確認。
- 日本語関節名・凡例・時系列説明を確認。
- 5動作の元時系列と4種類の対A比較をCSV／JSONへ出力し、対応関節数とデータ型を検証。
- GameSir模擬入力でスティック上右下左、十字キー上右下左、Rスティックで視点回転後の移動、入力解除後の待機を確認。移動方向とアバターの向きの誤差が0に近いことを確認。
- X Bot・AEGISの歩行・走行の姿勢を複数時刻で検査。GLBのスキニングボーン数は変更していない。

**実機Safari、GameSir、HMDでの最終検証は未実施**です。姿勢が数学的に有限でも、足の接地の自然さや身体スキルの良否を保証するものではありません。
